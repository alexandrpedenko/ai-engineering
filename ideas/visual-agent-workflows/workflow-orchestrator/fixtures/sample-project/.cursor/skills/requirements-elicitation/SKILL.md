# Requirements elicitation

Use this when you are given a brief and asked for requirements.

1. Read the brief and list who uses the product and what each of them needs to get done.
2. Write each requirement as one sentence: "<who> can <do what> so that <why>".
3. Number them `R1`, `R2`, … and group them by user.
4. For every requirement add an acceptance check: something a tester can do and observe.
5. List anything the brief leaves open under **Open questions**. Do not guess an answer.

Write the result to the file you are told to write, as markdown, with one section per user.
