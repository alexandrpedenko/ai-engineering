# Slice 5.6 — a Claude Agent SDK runtime

**Status:** built (2026-10-11), in review.

**Capability.** Run workflows on Claude instead of Cursor: set
`"runtime": "claude"` in `orchestrator.config.json` (or `ORCH_RUNTIME=claude`),
put `ANTHROPIC_API_KEY` in `workflow-orchestrator/.env`, and everything else
works as today: the terminal command, the browser, gates, retry, the file
check. The orchestrator has no Anthropic integration yet; this slice adds it.

```
$ ORCH_RUNTIME=claude npm run wf -- run ba-discovery --project /tmp/booking
run run-3c9e…
▸ elicit (attempt 1)
  · Reading discovery/brief.md
  · Write
✓ elicit  38 s  14.2k in / 2.9k out
    created  discovery/requirements.md
```

Decision: [ADR-0013](../adr/0013-runtime-chosen-per-project.md). Builds on
ADR-0004 (the runtime port), ADR-0005 (what goes in the message), ADR-0006
(no second run for one attempt), ADR-0007 (outputs from disk), and slice
5.5's start-failure handling.

Written against `@anthropic-ai/claude-agent-sdk` 0.3.296 (peers: `zod` ^4,
`@anthropic-ai/sdk` ≥ 0.93, `@modelcontextprotocol/sdk` ^1.29) and the
TypeScript reference at code.claude.com/docs/en/agent-sdk, read 2026-10-11.

## Design: one adapter, a strategy per provider

```
AgentRuntime (port, application)
   ▲
ProviderAgentRuntime ──uses──► AgentProvider (interface)
  · redacts the key from errors           ├─ CursorProvider   (@cursor/sdk; was CursorAgentRuntime)
  · remembers runs started here           └─ ClaudeProvider   (@anthropic-ai/claude-agent-sdk)
  · cut-off / unknown → "interrupted"
  · ProviderRun → RunHandle
createAgentProvider(kind, apiKey)        factory; CREDENTIALS = { cursor: "CURSOR_API_KEY", claude: "ANTHROPIC_API_KEY" }
```

```ts
interface ProviderRun { id; events(): AsyncIterable<StepEvent>; result(): Promise<AgentRunResult>; cancel(): Promise<void> }
interface AgentProvider {
  readonly name: "cursor" | "claude";
  open(request: AgentRunRequest): Promise<ProviderRun>;          // rejects if the agent can't start
  find(runId: string, cwd: string): Promise<ProviderRun | "cut-off" | null>;
}
```

Files under `core/src/infrastructure/agentRuntime/`: `AgentProvider.ts`,
`ProviderAgentRuntime.ts`, `createAgentProvider.ts`, `AsyncQueue.ts` (lets
one SDK stream feed both `events()` and `result()`),
`cursor/{CursorProvider,cursorMessages}.ts`,
`claude/{ClaudeProvider,ClaudeEventMapper}.ts` (a small stateful mapper: it
remembers each tool call's name so a later `tool_result` can be reported as
that tool completing). `CursorAgentRuntime` and its tests move into this
shape; behaviour is unchanged.

The port gains one optional field, `AgentRunRequest.subagents` (the
project's agent files: name, description, prompt), so a provider that
doesn't read `.cursor/agents` itself (Claude) can pass them on.

## How a step runs on Claude

`ClaudeAgentRuntime.start(request)` calls `query({ prompt: request.message, options })`:

| option | value | why |
| --- | --- | --- |
| `cwd` | the project root | the agent works in the project (ADR-0001) |
| `model` | `request.model.id` (default `claude-opus-5-5`) | ADR-0013 model map |
| `systemPrompt` | `{ type: "preset", preset: "claude_code" }` | keep Claude Code's own instructions for its tools; the persona stays in the message (ADR-0005) |
| `settingSources` | `["project"]` | the project's `.claude/settings.json`, `CLAUDE.md`, `.claude/skills` |
| `agents` | the project's agent files, as `{ description, prompt, model? }` | `.cursor/agents/*.md` reach Claude as subagents |
| `permissionMode` | `"acceptEdits"` | file edits without a person at a prompt |
| `allowedTools` / `disallowedTools` | allow `Read`, `Write`, `Edit`, `Glob`, `Grep`; disallow `Bash` | no shell commands until delivery steps need them (slice 8 decides) |
| `sessionId` | a new UUID per attempt | stored in the run ref, so the attempt can be identified later |
| `abortController` | one per run | `cancel()` aborts it |
| `env` | `{ ...process.env, ANTHROPIC_API_KEY }` | the key reaches the Claude Code process |

- `start` waits for the stream's `system/init` message before returning, so a
  refused key, an unknown model or a missing binary fails **in `start`**, and
  the step ends `failed: couldn't start the agent: …` (slice 5.5) instead of
  crashing.
- **Events** (`claudeMessages.ts`, like `cursorMessages.ts`): assistant `text`
  blocks → `text`; `tool_use` blocks → `tool` running; the matching
  `tool_result` → completed / error; `system` status → `status`. Tool inputs
  and outputs are not passed on.
- **Result**: the `result` message. `success` → `finished`, summary =
  `result`; `error_*` → `error`, summary = the joined `errors`; aborted →
  `cancelled`. `usage.input_tokens` / `output_tokens` → `Usage`;
  `duration_ms` → `durationMs`. (`total_cost_usd` is available; recording cost
  is a later slice.)
- **`attach(runId)`**: a run id this process started → its handle; otherwise
  a handle whose `wait()` returns `error`, "the agent run was interrupted (its
  process stopped)". Never `null` for a Claude session id, so a restart never
  starts a second run silently (ADR-0013).
- The API key never appears in errors, events or logs (same redaction as
  Cursor).
- `query` is injected (like `CursorSdk`), so tests never start Claude.
- `find` always answers `"cut-off"` for a Claude session not started by this
  process (ADR-0013: no reattach across restarts).

## Config and composition

```jsonc
{
  "runtime": "cursor",                       // or "claude"; ORCH_RUNTIME overrides
  "models": { "cursor": "composer-2.5", "claude": "claude-opus-5-5" }
}
```

- `defaultModel` (from slice 1) is replaced by `models[runtime]`. A config
  file that still has `defaultModel` is read as the Cursor default, so
  existing files keep working (`strictObject` would otherwise reject it).
- Composition picks the runtime when a step runs: fake → `FakeAgentRuntime`;
  `cursor` → `CursorAgentRuntime` (`CURSOR_API_KEY`); `claude` →
  `ClaudeAgentRuntime` (`ANTHROPIC_API_KEY`). A missing key is
  `MissingCredentialsError` naming the right variable (CLI exit 3, HTTP 503).
- `/api/health` answers `{ ok, node, runtime }`, and the app bar shows it
  ("runtime: claude"), so it's clear which agent will run.

## Done when

- `npm run check` passes.
- **One manual run on Claude** with your `ANTHROPIC_API_KEY` (costs a few
  agent runs on `claude-opus-5-5`; lower with `models.claude:
  "claude-sonnet-5-5"`), on a temp copy of the sample project, from the
  terminal: elicit writes `discovery/requirements.md`; reject once and the
  second attempt reflects the feedback; approve, design writes
  `discovery/design.md`. Then the same run once in the browser.
- The handover reports what happened, including output quality and cost
  (`total_cost_usd`).

## Not in this slice

- A runtime per workflow or per step (ADR-0013, alternatives).
- Discovering `.cursor/skills` the step doesn't list (a Claude plugin pointing
  at that folder is a possible later step).
- Recording cost per step and run.
- Shell access (`Bash`) for agents; decided with delivery steps (slice 8).

## Amendments

**2026-10-11, slice 5.6 build — two more allowed tools for Claude.**
Spec said: allow `Read`, `Write`, `Edit`, `Glob`, `Grep`.
Now: also `Skill` (so project skills in `.claude/skills` can be used) and
`Task` (so the subagents passed in can be called). `Bash` stays disallowed.
Why: without them the skills and subagents the runtime loads couldn't be used.

**2026-10-11, slice 5.6 build — the web port asks for health, not "is up".**
Spec said: the app bar shows the runtime.
Now: `OrchestratorApi.isServerUp(): boolean` became `health(): { up, runtime? }`;
`useServerStatus()` returns `{ status, runtime? }`; the chip reads
"server: up · runtime: claude".
Why: the runtime comes from the same `/api/health` answer.

**2026-10-11, slice 5.6 build — smaller differences.**
- Claude's input tokens include prompt-cache reads and writes (they're input
  the run consumed; the SDK reports them separately).
- `CursorAgentRuntime` and its tests are gone: the same behaviour is now
  `ProviderAgentRuntime` + `CursorProvider`, tested separately.
- A test helper `tests/infrastructure/agentRuntime/claude/messages.ts` builds
  SDK-shaped messages.
